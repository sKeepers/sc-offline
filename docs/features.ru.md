# Функции sc-offline 0.7.3 RU

Это описание возможностей локальной русской сборки на основе sc-offline v0.7.3. Мод использует оригинальный клиент Star Citizen и добавляет офлайн-песочницу. Он не воспроизводит полноценный сервер CIG и не даёт прохождение кампании Squadron 42.

**Статус проверки:** пользователь подтвердил работоспособность базовой сборки. Новое расширение Exploration 1 — [полёт, сохранения, задания и диагностика](exploration.ru.md) — требует отдельной проверки в игре.

## Меню и клавиши

**M** открывает и закрывает меню. В нём девять вкладок: «Игрок», «Перемещение», «Корабли», «Экипаж», «NPC», «Строительство», Squadron 42, «Сетевая сессия» и настройки меню.

| Клавиша | Действие |
| --- | --- |
| M | Открыть или закрыть меню |
| F6 | Включить или выключить строительство |
| F7 | Сохранить текущую позицию |
| F8 | Вернуться в сохранённую позицию |
| Backspace | Удалить последний размещённый объект в режиме строительства |

Списки кораблей, снаряжения, NPC и объектов находятся в текстовых файлах `data`. Приведённые ниже количества взяты из документации исходной версии: это число записей в списках, а не гарантия, что каждый объект доступен и исправен в установленном клиенте. Английское [описание файлов данных](data-files.md) объясняет их формат.

## Игрок

- Свободное перемещение без столкновений (noclip), бессмертие и бесконечные боеприпасы.
- Выбор снаряжения из 1489 записей `items.txt`, распределённых по десяти слотам.
- Локальный кошелёк aUEC. Баланс загружается при появлении персонажа и сохраняется при изменении в `data/storage/contracts.db` и `data/wallet.txt`.

В `wallet.txt` хранится только число. Его можно изменить при закрытой игре: изменённый файл имеет приоритет над балансом в базе. Если файла нет, используется `aUEC amount` из `data/OfflineDB/default_1.xml` — в исходном комплекте 100 000 000. Пока `wallet.txt` существует, стартовая сумма XML не применяется. Удаление `wallet.txt` сбрасывает сохранённый баланс и возвращает стартовую сумму.

## Перемещение

- Телепортация к планетам, спутникам, станциям, точкам Лагранжа и точкам перехода. Список `locations.txt` сгруппирован по звёздным системам.
- Сканирование загруженных мест с записью результата в `locations_found.txt`. Интерьеры и небольшие зоны скрыты, пока не включено их отображение.
- Именованные закладки в `data/storage/quantum.db`.
- Одна быстрая позиция: F7 сохраняет, F8 возвращает; хранение — `data/storage/teleport.db`.
- Закладки из старых `bookmarks.txt` и `spawn.txt` импортируются при первом запуске новой версии.

**Ограничения:** обычная телепортация не переносит между звёздными системами. Для доступа к Pyro и Nyx нужна загрузка `boot_map = PU_All`. Некоторые точки Pyro могут перенести на орбиту, поскольку в списке ещё отсутствует радиус места.

## Корабли и транспорт

- Создание транспорта из 1102 записей `ships.txt`. Поиск выбирает первое совпадение.
- Выбор посадки: пилотское кресло, кресло по имени, выбор после создания или создание без посадки. Занимающего кресло NPC можно удалить.
- Включение систем через игровое событие Flight Ready. У отдельных кораблей некоторые системы могут остаться выключенными.
- Бесконечные корабельные боеприпасы пополняют магазины корабля, в котором находится игрок.

## Терминалы кораблей, ангары и диспетчер

При `asop = on` мод добавляет офлайн-логику терминалов ASOP, личных ангаров, корабельного лифта и диспетчера ATC. В нашей конфигурации `asop_fleet_list = ships`: терминалы используют список `ships.txt`.

1. **Открыть терминал.** Вместо бесконечного «Stand by» появляется список кораблей.
2. **Доставить (Deliver).** Корабль создаётся примерно на три секунды на высоте 1000 м над игроком, затем помещается в локальное хранение станции. После «Awaiting Delivery» терминал показывает «Stored» и действие Retrieve.
3. **Получить (Retrieve).** Диспетчер выделяет личный ангар. Он появляется в списке лифтов станции. Корабельная платформа опускается, на ней создаётся корабль, затем она поднимается. Терминал показывает «On Pad» и действие Store.
4. **Убрать на хранение (Store).** Платформа опускается с кораблём и возвращается пустой. После этого корабль можно получить снова.
5. **Связаться с диспетчером.** Внутри ангара вызов открывает двери для вылета; они закрываются после выхода. При запросе посадки снаружи назначается площадка с меткой на HUD. На другой станции создаётся ангар этой станции, и хранение привязывается к ней.

Для действия Deliver нужна включённая игровая система доставки. Мод выставляет `g_itemRecovery.deliverySystemSetup 1`. Фильтр «Show local ships» показывает только корабли этой станции, поэтому до первой доставки список может быть пуст.

**Ограничения:** одновременно выдаётся один корабль. Хранение действует только в текущей сессии. Получение создаёт новый корабль того же класса: повреждения, груз и изменения оснащения не переносятся. Авторы пробовали только малые и средние ангары.

Если нужный игровой код не найден, соответствующая часть отключается. В `mod.log` перечисляются доступные и отсутствующие части, например `ready` или `MISSING`. При `asop = off` весь этот набор выключен. Операции терминала отмечены `[asop]`, ангаров — `[iim]`, диспетчера — `[atc]`.

Для плагинов доступны возможности `asop.terminal`, `asop.caller`, `asop.list`, `asop.deliver`, `asop.claim_timeout`, `asop.retrieve`, `hangar.lift`, `atc.store`, `hangar.instance`, `atc.tokens`, `asop.diagnostics`. Полученный через терминал корабль регистрируется во встроенном модуле создания объектов, что позволяет плагинам перемещать его через `set_entity_transform`.

## Экипаж

Вкладка показывает кресла корабля и показывает, кто занимает каждое место. Можно сесть самому, поднять NPC с кресла, удалить его или добавить нового. Добавленные NPC занимают места, но не пилотируют корабль и не управляют турелями как полноценная команда.

## NPC

Создание персонажей перед игроком из 2239 архетипов `npcs.txt` и удаление созданных персонажей. Если игра не позволяет удалить NPC офлайн, мод перемещает его далеко за пределы видимости. Наличие архетипа не гарантирует работоспособное поведение или миссии для него.

## Строительство

- Свободное размещение объектов; F6 включает режим.
- 3728 записей `buildables.txt` в 18 группах.
- Пока камера движется, сборная постройка обозначается флагом; после остановки показывается сама постройка.
- Отмена последнего размещения и очистка всех объектов базы.

Полное сохранение построенного мира между запусками в этом описании не заявлено. Сохранённая закладка позиции не является сохранением базы.

## Контракты

`contract_scripts.txt` содержит 796 контрактов, рассчитанных на выполнение без миссионных сценариев CIG, например перевозки. Список mobiGlas исключает контракты Pyro и Nyx, а также записи с именами test, debug или tutorial. Реальные количества известных и выполняемых контрактов записываются в `mod.log` как `[contracts] N contracts known; M run ...`.

В комплекте нет миссионных сценариев Subsumption от CIG. Зависимые от них задания — охота за головами, доставка с боем, salvage и другие — не предлагаются. Наличие строки в файле не означает, что контракт проверен на нашем клиенте.

## Squadron 42

При первом открытии вкладки появляется предупреждение о спойлерах: подтверждение открывает вкладку, возврат переводит на первую вкладку меню. Это доступ к отдельным материалам и настройкам клиента, а не кампания Squadron 42.

- **Костюмы.** 35 комплектов из `outfits.txt`, поиск и надевание выбранного комплекта. Если голова не указана, используется стандартное лицо. Неизвестные предметы пропускаются, их количество записывается в журнал. Настройка HUD визора SQ42 применяется при следующем надевании предметов или костюма.
- **Настройки.** Автонаведение SQ42, мини-карта визора, декоративные элементы визора и интерфейс начального меню SQ42. Переключатели недоступны до чтения текущего значения из игры. Изменения действуют до конца сессии; `USER.cfg` не изменяется.
- **Объекты.** Размещение 60 записей группы `[sq42]` без включения строительства. Они добавляются к базе и удаляются обычными действиями отмены и очистки.
- **Корабли.** Idris-P, Gladius, Retaliator, Starfarer, Avenger Stalker, Hornet, группа Vanduul и варианты Bengal. Отсутствующие в клиенте классы недоступны. Корабли игрока создаются на 30 м выше и используют правила посадки вкладки кораблей; Vanduul — на 300 м выше и атакуют игрока; Bengal — на 1500 м выше. Вариант «Bengal + Vanduul» добавляет группу только при наличии её классов.
- **Экипаж.** Созданный здесь корабль становится выбранным кораблём вкладки экипажа. Исключение — группа Vanduul, сопровождающая Bengal.
- **Консоль.** Ввод команды и её выполнение через Enter или кнопку запуска. Результат записывается в `Game.log`, а не выводится в меню.

## Оформление меню

Можно добавить `data/menu_background.png` или `.jpg` и перезапустить игру. В настройках меню выбираются затемнение и размещение фонового изображения.

## Журналы и квантовый двигатель Gladius

`data/mod.log` содержит действия мода и его версию. При запуске выводится отчёт `[core] signatures: N/N OK`; отсутствующие или неразрешённые адреса отмечаются `MISSING`, `AMBIG`, `FAILED`, `BLOCKED` с причиной. Сообщения строки состояния меню записываются с префиксом `[status]`. Журнал лаунчера — `data/launcher.log`, игры — `Game.log` в папке установки.

Новые параметры квантового двигателя Gladius (Wetkah Beacon) задаёт встроенный пакет `data/builtin/quantum/datacore/quantum_drive.toml`. Загрузчик sco-core применяет его к DataCore `Data/Game2.dcb` во время чтения через адаптер CryPak. В исходном описании управление указано как удержание Caps Lock либо B для режима NAV и затем удержание левой кнопки мыши; фактические привязки зависят от настроек игры.

Пакет обращается к именам записей и полей. Если они сохранились после обновления, изменения могут применяться; если поле удалено или переименовано, пакет целиком пропускается, и игра получает свои исходные данные. В журнале видны загрузка пакета, `[datacore] ... quantum 508/508 applied` и результат `[pak]`, либо причина отказа. Возможность `quantum.drive` включается только после успешного применения.

Для разработчика: `sco-dcb check <Game2.dcb> data/builtin/quantum` проверяет пакет без запуска игры; код выхода 0 означает, что все операции применимы. Это отдельная утилита sco-core, её наличие в пользовательском пакете не подразумевается.

## Дополнительные плагины

Поддерживаются плагины SDK sco-core: DLL, сценарии Lua и пакеты данных. В нашей сборке их загрузка выключена: `plugins = off`.

Чтобы включить дополнительные плагины:

1. При закрытой игре установить `plugins = on` в `sc-offline.ini`.
2. Разместить каждый плагин в отдельной папке `data/plugins/<id>/` с его `plugin.ini` и файлами. Пример: `data/plugins/hello/plugin.ini` и `hello.dll`.
3. После запуска проверить отчёт `[plugin]` в `mod.log`. Неподходящая версия API или отсутствующая возможность будут указаны как причина отказа; остальные плагины продолжают загружаться.

Пустой файл `disabled` в папке плагина отключает только его. Дополнительный плагин выполняет код внутри игры, поэтому имеет смысл использовать только понятный и проверенный код.

### Встроенные модули

В исходной версии десять модулей включены в `dinput8.dll`: `teleport`, `spawn`, `crew`, `loadout`, `npc`, `ammo`, `quantum`, `build`, `contracts`, `multiplayer`. В Exploration 1 добавлен одиннадцатый модуль `exploration`. Они загружаются в этом порядке независимо от `plugins = off`; выключаются только сторонние плагины.

Встроенные модули выполняют периодическую работу через подписку на `tick`, рисуют свои вкладки через `sco.ui` и привязывают клавиши. Обработанная ошибка в таком вызове может отключить конкретный модуль и его вкладки; это не гарантирует защиту от любых сбоев игры или повреждения памяти.

### Команды для авторов плагинов

Это команды API `invoke` в SDK, а не обещание, что каждую из них можно вводить в штатную игровую консоль. Имена команд и аргументов оставлены без перевода.

| Команда | Действие |
| --- | --- |
| `teleport.save` | Сохранить текущую позицию; F7 |
| `teleport.go` | Вернуться в сохранённую позицию; F8 |
| `spawn.ship <class> <height>` | Создать корабль на высоте 0–10000 м над игроком и выбрать его для экипажа |
| `crew.target` | Выбрать для экипажа корабль, в котором находится игрок |
| `crew.sit <seat>` | Занять первое кресло с совпадением в имени, удалив занимающего его NPC |
| `crew.stand_all` | Поднять игрока и NPC с кресел выбранного корабля |
| `crew.fill <npc>` | Заполнить пустые кресла указанным архетипом NPC |
| `crew.clear` | Удалить NPC из кресел выбранного корабля |
| `crew.power_on` | Передать выбранному кораблю событие Flight Ready |
| `npc.spawn <npc> <count>` | Создать перед игроком 1–10 NPC указанного архетипа |
| `npc.clear` | Удалить созданных NPC |
| `loadout.equip <items>` | Надеть предметы из `items.txt`, по одному на слот; разделители — пробелы или запятые; остальные слоты пусты |
| `loadout.wear <outfit>` | Надеть комплект Squadron 42 из `outfits.txt` |
| `ammo.infinite <on>` | Включить или выключить бесконечные боеприпасы; флажок меню не синхронизируется с этой командой |
| `ammo.ship_infinite <on>` | Включить или выключить бесконечные корабельные боеприпасы |
| `quantum.travel <place> <altitude>` | Телепортироваться к месту из вкладки перемещения на высоту 100–20000 м |
| `quantum.bookmark <name>` | Перейти к именованной закладке |
| `quantum.save_bookmark <name>` | Сохранить именованную точку; пустое имя заменяется именем зоны |
| `quantum.scan` | Записать загруженные места в `locations_found.txt` |
| `build.toggle` | Переключить строительство; F6 |
| `build.undo` | Удалить последний размещённый объект |
| `build.clear` | Удалить все размещённые объекты |
| `build.place <object> <ahead>` | Разместить объект на расстоянии 0–100 м перед игроком без включения строительства |
| `contracts.status` | Показать количества известных, предлагаемых и выполняемых контрактов и баланс |
| `multiplayer.status` | Показать состояние сессии и количество других игроков |
| `multiplayer.leave` | Выйти из сессии или прекратить её размещение |
| `multiplayer.goto <player>` | Перейти к визуальной копии игрока |

Команды требуют доступности соответствующей игровой функции. Если адреса не найдены, возможность отсутствует, но остальные части системы могут работать. Выполненная команда, которая не смогла завершить действие, возвращает `failed` и причину. Идентификаторы встроенных модулей заняты: сторонний плагин с именем `teleport`, `spawn`, `crew` и т. п. отклоняется.

### Сервисы создания объектов и координат

`spawn.entities` 1.2 предоставляет таблицу C-функций: создание объектов рядом с игроком, ID персонажа и корабля, проверку существования объекта (`entity_alive`) и изменение позиции/поворота (`set_entity_transform`) в координатах мира или зоны. Плагин может перемещать объекты, созданные от его имени через `spawn_as`, и зарегистрированный модом корабль игрока. При выгрузке плагина его регистрация объектов забывается. Старые версии 1.0/1.1 совместимы; перед обращением к новым полям нужно проверять размер таблицы `size`. Заголовок — `sc_spawn.h` в sco-core, получение сервиса — через `query_service`.

`teleport.spatial` 1.0 (`sc_spatial.h`) предоставляет позицию и ориентацию игрока, зону объекта, имя зоны и преобразования между координатами зон и мира. Зоны вложены: система → планета → город/станция → корабль → помещение. ID — 64-битные игровые значения, расстояния — в метрах. Данные зон обновляются каждый игровой такт; выгруженный объект может возвращать ID 0. Оба сервиса вызываются только из игрового потока.

### Вкладки, клавиши и завершение игры

Плагин может добавить вкладку ImGui, отметку возле заголовка, наложение и свободное сочетание клавиш, например `ctrl+alt+9`. M и клавиши строительства зарезервированы модом. Подробности и таблица клавиш — в английском [описании интерфейса плагинов](plugin-ui.md).

При штатном выходе через меню или `quit` плагины получают `game.exit` и выгружаются: новые первыми, встроенные последними. В журнале появляется `[app] game closing ...`, затем строки `[plugin] unloaded ...`. При сбое или принудительном завершении этого события нет; важные данные нельзя сохранять только при выходе.

## Сетевая сессия: LAN или VPN

Каждый участник запускает собственную офлайн-игру. Через `sco.net` передаются сведения о положении игроков и кораблях; в вашем мире создаются и перемещаются их визуальные копии («призраки»). Игровой сетевой код CIG не используется. Соединение начинается только после «Создать сессию» или «Подключиться».

**Создание:** M → «Сетевая сессия» → имя, парольная фраза минимум из восьми символов, UDP-порт (по умолчанию 64091) → создание сессии. Другим нужны LAN-адрес компьютера, порт и фраза.

**Подключение:** указать имя, адрес ведущего, порт и ту же фразу. Ошибка пароля, заполненная сессия или отсутствие ответа отображаются в состоянии подключения. Максимум — восемь игроков.

По умолчанию доступны частные IPv4-сети `10.x`, `172.16–31.x`, `192.168.x` и link-local. Для VPN добавляется его диапазон в `multiplayer_allow`, например `100.64.0.0/10` для Tailscale. С включённым `block_network` лаунчер оставляет разрешённые сети доступными и блокирует прочий сетевой доступ игры. Правила восстанавливаются после выхода.

Сообщения аутентифицируются парольной фразой, но не шифруются. Передаются выбранное имя, классы персонажа/корабля и положение. Фраза сохраняется только при включённом «Запомнить», в незашифрованном виде в `data/storage/multiplayer.db`; в `mod.log` она не записывается.

Вкладка показывает состояние копий: загрузка, отображение, скрытие за пределами 10 км или перемещение из видимой области, если зона другого игрока ещё не загружена. Координаты передаются относительно зон с совпадающими именами. Игрок на корабле отображается кораблём, если класс доступен; показ кораблей можно выключить. Иначе используется NPC, обычно невооружённый гражданский. Действие перехода перемещает к копии участника. Обновление положения идёт примерно с шагом 0,1 с; задержка сети добавляется отдельно.

**Ограничения:** общей физики и надёжных столкновений нет; урон, задания, инвентарь, деньги и снаряжение не синхронизируются. Нет голосовой связи и чата. Созданные NPC, объекты базы и прочий мир остаются личными; передаются только игрок и корабль, в котором он находится. Используется IPv4. `multiplayer = off` скрывает вкладку. Журнал использует префиксы `[multiplayer]` и `[net]`.

## Связь с другими играми: только отдельные экспериментальные сборки

В исходниках есть TitanLink для Titanfall 2 через Northstar и voxel bridge для игры с блоками в стиле Minecraft. Они работают через локальную общую память `sco.ipc` в рамках пользователя Windows, без сетевого соединения.

**В нашей обычной сборке их нет:** параметры CMake `SCO_BRIDGE_TITANLINK` и `SCO_BRIDGE_VOXEL` выключены. Для работы нужна отдельная сборка и вторая часть интеграции внутри другой игры, которая этим проектом не поставляется. Предусмотренные клавиши экспериментальных сборок — F9 и Ctrl+F9. Описание — в английском [bridges.md](bridges.md).

## Что недоступно офлайн

- Создание и настройка персонажа через штатное начальное меню: оно пропускается.
- Имущество аккаунта — его корабли, предметы и ангар.
- Обычный выбор места появления. Используется старт игры либо предусмотренный запуск над Daymar через `start = Daymar`.
- Выбор корабля в штатном менеджере транспорта mobiGlas, хотя он может показывать локально хранимые/выданные корабли. Используйте терминал или вкладку «Корабли».
- Полноценный общий серверный мир и сохранение состояния всех объектов между запусками.

## Что ещё требует проверки

В документации исходного ChrisWareOffline отдельно отмечены функции, добавленные после последнего игрового теста: пополнение энергетического оружия, удаление NPC через handle объекта, вставание из кресла, предпросмотр настоящей сборной постройки и названия Pyro/Nyx после нового сканирования. На нашем ПК пользователь подтвердил локальный запуск; проверка каждой функции и нового расширения остаётся отдельным этапом.

## Сохранения

Подтверждённая структура хранения мода — отдельные базы SQLite `data/storage/teleport.db`, `quantum.db` и `contracts.db` для быстрой позиции, закладок и баланса. Запись транзакционная: сбой оставляет старое или новое сохранение вместо половины записи.

Старые `spawn.txt` и `bookmarks.txt` импортируются и сохраняются как файлы; последующее изменение файла вызывает повторный импорт. `wallet.txt` продолжает обновляться и имеет приоритет, если изменён после последней записи мода. При недоступной базе соответствующий модуль пишет причину в журнал и использует текстовый файл. Эти сохранения не включают весь мир, груз, повреждения корабля или полное состояние персонажа.

## Настройки нашей русской сборки

| Ключ `sc-offline.ini` | Назначение |
| --- | --- |
| `game` | Путь к установке; без него лаунчер ищет и запоминает найденную игру |
| `channel = LIVE` | Канал установки |
| `boot_map = PU_All` | Загрузка карты всех систем |
| `start = Daymar` | Необязательный старт над Daymar; пустое значение — стандартный старт |
| `start_ship = DRAK_Cutlass_Black` | Корабль для предусмотренного старта; без `start = Daymar` место появления не меняется |
| `asop = on` | Терминалы, ангары и диспетчер |
| `asop_fleet_list = ships` | Список кораблей из файла мода |
| `plugins = off` | Сторонние плагины выключены; встроенные работают |
| `multiplayer = on` | Вкладка LAN/VPN; сессия не начинается автоматически |
| `multiplayer_allow` | Дополнительные диапазоны IPv4 для VPN |
| `block_network = on` | Временная блокировка сетевого доступа игры с предусмотренными исключениями для LAN/VPN |
| `eac_hosts = on`, `eac_rename = on` | Временные действия помощника для запуска без EAC, с восстановлением после выхода |
| `clean_logs = off` | Сохранять журналы |
| `crash_reports = on` | Предлагать локальный отчёт о сбое; без автоматической отправки |
| `discord_presence = off` | Не публиковать статус игры в Discord |
| `check_updates = off` | Не заменять русский пакет оригинальным обновлением |

Настройки изменяются при закрытой игре. Помощник лаунчера временно меняет правила брандмауэра, hosts и имя общего исполняемого файла EAC. Отдельная копия клиента не изолирует эти системные действия. После сбоя проверяйте состояние в лаунчере и при необходимости используйте удаление мода для восстановления.
