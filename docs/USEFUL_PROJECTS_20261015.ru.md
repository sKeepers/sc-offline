## 1. SC Tracker — лучший кандидат для событий миссий

verdantnebula/sc-tracker, 64ee97ec25cee2a9de56f2c49cabb29d00b8bf77, MIT.
Прочитаны logParsers.ts, logWatcher.ts и realLogE2E.test.ts. Есть разбор принятия
миссий, целей, завершения, мест и грузовых этапов; ротация/обрезка и исторический
backfill. В репозитории есть обезличенные fixtures; их тесты нами не запускались.

Наш observer уже различает диагностические события и устраняет повторы.
Польза аналога — смысловое сопоставление миссии и этапов доставки. В последних8МБ
нашего Game.log не встретились Contract Accepted, RequestLocationInventory,
mission_id и objective_id. Это ограниченная выборка, не доказательство отсутствия
событий во всём клиенте. Нужны реальные строки4.10.x и свои тесты совместимости.
Запрос инвентаря показывает запрос/место, а не список вещей; payout журнала не
подтверждает зачисление нашего ledger. Старые записи не должны давать уведомления.
Следующий шаг: одна игровая миссия → обезличенный пример → ограниченный адаптер.
https://github.com/verdantnebula/sc-tracker/tree/64ee97ec25cee2a9de56f2c49cabb29d00b8bf77

## 2. ScDataDumper — контейнеры и схемы

octfx/ScDataDumper, 99292bf04bbc03d4cb99c680ea336bcae17e733a.
MIT указан в composer.json; отдельного root LICENSE в просмотренном дереве нет.
Прочитаны InventoryContainerResolver, InventoryContainer и тесты resolver.
Разделены основной контейнер, loadout-контейнеры и шкафчики из socpak. Двойной
подсчёт устраняется по UUID, порту и экземпляру/размещению. Это полезно для нашей
будущей карточки вместимости и диагностики контейнеров. Есть schema:diff для
сравнения структур между патчами. Собственная совместимость с4.10.2 не проверена.
В коде есть TODO: PersonalStorage определяется по префиксу, что может пропускать
переименованные классы. Это разбор статических данных, не готовая выдача в инвентарь.
Следующий шаг: независимо разобрать одну Andromeda и сохранить источник каждого поля.
https://github.com/octfx/ScDataDumper/tree/99292bf04bbc03d4cb99c680ea336bcae17e733a
