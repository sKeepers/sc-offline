# Локализация лаунчера и названий из игры

В Local 4 тексты лаунчера загружаются из `localization/launcher/<код>.ini`.
Формат — плоский UTF-8 `ключ = перевод`, без новой библиотеки JSON.
Английский шаблон: `en.ini`; русский перевод: `ru.ini`.
Английские тексты также встроены в EXE: при отсутствии файла, строки или при
небезопасном переводе программа использует английский текст для этой строки.

В профиле свободного полёта можно сохранить язык лаунчера и источник названий.
Изменения применяются после закрытия и повторного запуска лаунчера.

```ini
language = auto
game_language = auto
```

`language`: `auto`, `en`, `ru` или код собственного каталога (`de`, `fr`, `ja`…).
`auto` читает `g_language` из `<канал>/user.cfg`, учитывает подписи из
`data/languages.ini`, затем использует язык Windows, если настройка игры отсутствует.
Например, папка `korean_(south_korea)` с подписью «Русский» определяется как `ru`.
Настройка языка аудио игнорируется. Если выбранного каталога лаунчера нет,
интерфейс остаётся английским; наличие перевода игры не создаёт перевод кнопок.

`game_language`: `auto` или имя установленной папки, например `german_(germany)`.
Этот параметр выбирает только источник читаемых названий, а не язык самой игры.
При `auto` вместе с автоматическим языком интерфейса используется активный пакет
игры; при явно заданном языке интерфейса ищется пакет для этого языка.
При отсутствующем пакете остаётся читаемое имя класса.

Пакеты обнаруживаются в `<канал>/data/Localization/*/global.ini`.
Читаются только локальные файлы; исходные игровые данные не копируются в поставку,
не редактируются и не отправляются внешним сервисам.
Название из `vehicle_Name*`/`item_Name*` меняет отображение, но идентификатор
корабля/предмета сохраняется. Лаунчер использует эти названия для выбора корабля;
мод получает выбранную папку через `SC_OFFLINE_GAME_LANGUAGE` и использует её
в списках кораблей и снаряжения. Поиск проверяет название и исходный класс.

## Новый язык интерфейса

1. Скопируйте `en.ini` в `<код>.ini` рядом с ним.
2. Переводите только значения. Ключи постоянные: не переименовывайте их при правке текста.
3. Сохраните файл в UTF-8. Выберите язык в профиле и перезапустите лаунчер.
4. Выполните `python tools/check_localization.py` из каталога исходников.

Последовательности `\n`, `\r`, `\t`, `\\` означают перевод строки, возврат каретки,
табуляцию и обратную косую черту. `\s` сохраняет пробел в начале/конце значения.
Комментарии начинаются с `#` или `;` на отдельной строке. Деление производится
по первому `=`; значение может содержать дополнительные `=`.
Параметры printf (`%s`, `%ls`, `%d`, `%zu`…) должны совпадать с английским
шаблоном по порядку и типу. Нельзя менять скрытый суффикс `##id`.
Повторный ключ, некорректный UTF-8, неизвестная escape-последовательность или
несовместимые параметры не исполняются как команды.

ID интерактивных элементов привязаны к ключу каталога, а не переводу.
Нативные диалоги получают UTF-16; ImGui — UTF-8.
Используются системные Segoe UI и доступные дополнительные шрифты для CJK.
Проверка `--fonts` сравнивает cmap системных шрифтов; она не заменяет визуальную
проверку, поддержку арабского формирования букв или направления справа налево.

## Границы первого этапа

Это рекомендованный в issue #121 этап launcher-first. Основные тексты лаунчера,
его диагностика и профиль вынесены в 306 ключей. Содержимое описаний сторонних
плагинов и внешних журналов не переводится автоматически. Интерфейс меню M,
тексты собственных плагинов и веб-панели пока остаются прежними русскими.
Их общий языковой API следует делать отдельным добавочным C-сервисом sco-core,
после чего обновлять pin; текущий ABI плагинов не изменён.

Рекомендации разработчика: https://github.com/scubamount/sc-offline/issues/121#issuecomment-6129812798
